# Working on Digital Detective

- Inspect the existing code and understand the relevant architecture before changing it.
- Make the smallest reasonable change; favor simple, understandable modules.
- Avoid unnecessary abstractions, dead code, duplicate implementations, and dependencies.
- Write or update tests for behavior you change, then run the relevant tests.
- Never fabricate package APIs, dataset structures, documentation details, or benchmark results; verify external documentation when uncertain.
- Keep experiments reproducible and separate research or experimental code from core code.
- Explain important architectural decisions in change summaries.
- Stop and ask for clarification when a requirement is genuinely ambiguous rather than guessing.
